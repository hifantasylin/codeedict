# 可维护性审查清单

> 审查官可在审查报告中引用这些模式 ID，如 `> ✅ MNT-01 已覆盖`。

| ID | 检查项 | 说明 |
|----|--------|------|
| MNT-01 | 函数/方法长度 | 新增函数是否超过建议行数（如 50 行），是否可拆分为更小的职责单元 |
| MNT-02 | 圈复杂度 | 新增控制流（if/for/while/switch 嵌套）是否超过阈值（如 3 层嵌套），是否可通过守卫子句/策略模式降低 |
| MNT-03 | 代码重复 | 新增代码是否与项目中已有代码模式重复，是否应抽取公共函数/工具类 |
| MNT-04 | 命名清晰度 | 新增函数/变量命名是否遵循项目命名规则（参考 .codeedict/project-context.md「命名规则」章节），自解释还是需要读实现 |
| MNT-05 | 模块耦合 | 新增 import 是否引入跨层依赖（如 UI 直接调 DB），是否打破 .codeedict/project-context.md「架构分层」约束 |
| MNT-06 | 注释临时/来源标注 | 新增注释是否带**临时方案标注**或**外部来源标注**，如"阶段N/P0N/P1N"方案阶段、"借鉴/对标/对齐/参考 xxx项目"。这些是当下方案的临时划分或来源追溯，入库后污染代码且无持久价值。注释应只保留有持久价值的技术说明，用描述性语言 |

## 审查引用方式

审查报告中：

```
## 可维护性

| ID | 检查项 | 结论 |
|----|--------|:---:|
| MNT-01 | 函数长度 | ✅ 已覆盖 — 新增函数 20 行，适中 |
| MNT-02 | 圈复杂度 | 🆕 新发现 — login.ts:45-52 嵌套 4 层，建议拆为守卫子句 |
```
