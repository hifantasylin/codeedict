# 正确性审查清单

> 审查官可在审查报告中引用这些模式 ID，如 `> ✅ COR-01 已覆盖`。

| ID | 检查项 | 说明 |
|----|--------|------|
| COR-01 | 异常处理覆盖 | 新增代码中 IO/网络/DB/外部调用的异常是否被捕获并处理（日志/降级/用户提示），而非静默吞掉或直接崩溃 |
| COR-02 | 边界值处理 | 新增代码是否覆盖了空值/空列表/负数/0/超长输入/特殊字符等边界情况 |
| COR-03 | 测试补全 | proposal 中是否明确了新增代码的测试策略（新增用例/修改已有用例/回归范围），提及的测试是否覆盖了变更路径 |
| COR-04 | 状态变更一致性 | enum/常量/接口变更时，是否搜索了全项目引用并同步更新所有调用方 |
| COR-05 | 并发/竞态安全 | 新增代码是否涉及多线程/异步操作，是否考虑了竞态条件（锁/原子操作/不可变设计） |

## 审查引用方式

审查报告中：

```
## 正确性

| ID | 检查项 | 结论 |
|----|--------|:---:|
| COR-01 | 异常处理 | ✅ 已覆盖 — 网络请求有 try-catch 和降级 |
| COR-03 | 测试补全 | 🆕 新发现 — 新增代码缺少测试覆盖 |
```
